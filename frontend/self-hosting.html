Self-Host veedeeoh On Your Home Server

Run your own instance with Docker or from source. Free forever, no account with us, and no data of yours passing through anything we operate. You will need your own Supabase project, which is free at this size.

Step 1: Create your database

Required first, and the step most guides leave out

veedeeoh keeps accounts, profiles, watch history and watch parties in Supabase. There is no shared or default database: your instance uses a project you own, and nothing you do reaches ours.

Create a free project, then apply this repository's migrations to it. They build the whole schema, including the row-level security policies that keep one account's data away from another's.

git clone https://github.com/ItsCodejac/veedeeoh.git cd veedeeoh # Point the CLI at the project you just created npx supabase link --project-ref YOUR-PROJECT-REF # Create every table, policy and function npx supabase db push --include-all

--include-all matters: the baseline migration is dated ahead of the rest so it runs first, and without the flag the CLI skips it as out of order.

To check the result before trusting it, npm run verify:db builds a throwaway database from the migrations alone and asserts that signup, profile isolation, the seat cap, anonymous refusal and account deletion all behave. It needs psql and initdb on your PATH.

Then copy the project URL and anon key from Project Settings → API. The anon key is safe to publish; it ends up in the JavaScript either way, and row-level security is what actually protects the data. The service role key is not needed unless you want account deletion to work.

Step 2, option A: Docker Compose

Any Linux server, NAS, Unraid, or a Raspberry Pi

The repository ships a docker-compose.yml. Fill in your database details and bring it up:

cp .env.example .env # edit .env: SUPABASE_URL and SUPABASE_ANON_KEY docker compose up --build

Your instance is at http://localhost:8321.

It builds from source rather than pulling an image, and it has to. The database URL and anon key are compiled into the JavaScript bundle, so an image built by somebody else is an image pointed at somebody else's database. That is also why changing either value needs --build and not just a restart.

Step 2, option B: From source

For development, or hosting without Docker
cp frontend/.env.example frontend/.env # edit frontend/.env: VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY npm install # API and stream proxy on :8321 cd backend && npm run dev # In a second terminal: the app on :5173, proxying to the backend cd frontend && npm run dev

For a production build instead, npm run build from the repository root writes the static site to src/tvlc/static/, which backend/server.ts then serves on its own.

If the build stops with Cannot build: VITE_SUPABASE_URL is not set, that is deliberate. It used to fall back to veedeeoh.com's own project, which meant a self-hosted instance silently signed its users into our database. A build that stops and names the variable is the better failure.

Environment variables

Two are required. The rest turn optional things on.
VariableRequiredDescription
SUPABASE_URL
VITE_SUPABASE_URL		 Yes Your Supabase project URL. The VITE_ copy is read at build time and compiled into the bundle; the plain one is read by the server at run time. Docker Compose passes one value to both.
SUPABASE_ANON_KEY
VITE_SUPABASE_ANON_KEY		 Yes The project's anonymous key. Public by design and protected by row-level security, which is why applying the migrations matters.
SUPABASE_SERVICE_ROLE_KEY No Only used by account deletion, which has to remove a user from auth.users. Unset, that one endpoint answers 501 and says why. Bypasses row-level security — server-side only, and never with a VITE_ prefix.
PARTY_WORKER_URL No Your own watch party relay, if you run one. See worker/. Left blank, the app works normally and the party screen says parties are not configured on this deployment.
PROXY_URL No Absolute base for the stream proxy when it is not served from the same origin as the app.
PORT No HTTP port the server listens on. Defaults to 8321.

What a self-hosted instance does not do

So you are not left wondering whether it broke

Browsing, streaming, profiles, My List and resume all work exactly as they do on veedeeoh.com. Three things are part of the hosted deployment and are absent here on purpose: subscription billing, the transactional email that sends confirmation and password-reset messages, and the nightly jobs that warm the catalogue and send trial reminders.

Their endpoints answer 501 with an explanation rather than failing in some less obvious way. Sign-up email still works — it comes from Supabase's own mailer unless you configure otherwise.

Watch parties need a relay, which is a Cloudflare Worker in worker/. Deploy your own and set PARTY_WORKER_URL. The relay verifies callers against your project's JWT secret, so it will only accept your own users.
